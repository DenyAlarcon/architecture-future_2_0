# TCO-анализ

Оценка дана в условных единицах за 3 года. Это не точная смета, а сравнение текущей и целевой архитектуры по основным статьям затрат.

## Основные допущения

| Допущение | Значение |
| --- | --- |
| Горизонт расчёта | 3 года |
| Текущая архитектура | SQL Server 2008 DWH, Apache Camel, ручные доработки отчётов |
| Целевая архитектура | Data Lakehouse, события, каталог данных, self-service BI |
| Миграция | В первый год целевая архитектура дороже из-за внедрения и обучения |
| Старые системы | Постепенно выводятся из активного использования |

## Сравнение по статьям затрат за 3 года

| Статья затрат | Текущая архитектура | Целевая архитектура | Комментарий |
| --- | ---: | ---: | --- |
| Инфраструктура | 900 | 1050 | В целевой архитектуре больше компонентов, поэтому инфраструктура дороже |
| Лицензии | 750 | 420 | Часть дорогих лицензий DWH и старых BI-доработок постепенно уходит |

| Время аналитиков | 720 | 360 | Self-service BI и каталог снижают ручную работу аналитиков |
| Миграция и обучение | 0 | 450 | Нужны пилот, перенос отчётов и обучение доменных команд |
| Ручные сверки и исправления | 360 | 180 | События, каталог и проверки качества уменьшают число ручных сверок |
| Итого за 3 года | 3630 | 3150 | Целевая архитектура дешевле на горизонте трёх лет |

## Сравнение по годам

| Год | Текущая архитектура | Целевая архитектура | Комментарий |
| --- | ---: | ---: | --- |
| Год 1 | 1210 | 1370 | Внедрение платформы, пилот Data Mesh, обучение |
| Год 2 | 1210 | 980 | Масштабирование доменов и перенос части отчётов |
| Год 3 | 1210 | 800 | Меньше ручной поддержки и меньше зависимости от старых систем |
| Итого | 3630 | 3150 | Экономия за 3 года: 480 условных единиц |

## Экономическое обоснование

Целевая архитектура дороже в первый год, потому что нужно внедрить платформу событий, каталог данных и первые наборы данных. Экономия появляется на втором и третьем году за счёт:

- уменьшения ручных доработок в DWH;
- снижения зависимости от Apache Camel;
- более быстрого подключения новых источников данных;
- самостоятельного построения отчётов бизнес-пользователями;
- понятных владельцев данных в доменах.

Главный эффект для бизнеса — быстрее подключать новые направления и получать отчёты без долгой очереди к аналитикам.
