# Роадмап внедрения Data Mesh

## Роли

| Роль | Зона ответственности |
| --- | --- |
| Data Product Owner | Отвечает за наборы данных домена, качество и описание |
| Data Engineer | Настраивает загрузку данных, события и таблицы платформы данных |
| BI-аналитик | Помогает бизнесу строить отчёты и описывает метрики |
| Архитектор | Следит за границами доменов, стандартами и целевой архитектурой |
| Специалист ИБ | Настраивает доступ, аудит и правила работы с чувствительными данными |

## План на 3 года

| Период | Этап | Основные действия | Ключевые роли | Бизнес-цель |
| --- | --- | --- | --- | --- |
| Год 1, 1 квартал | Подготовка | Утвердить домены, назначить владельцев данных, описать первые правила доступа | Архитектор, Data Product Owner, специалист ИБ | Понять, кто отвечает за данные |
| Год 1, 2-3 квартал | Пилот | Запустить пилот на пациентском потоке и финансовых сервисах, опубликовать первые события и наборы данных | Data Product Owner, Data Engineer, BI-аналитик | Проверить подход на важных данных |
| Год 1, 4 квартал | Первые отчёты | Подключить каталог данных и первые отчёты в портале самообслуживания | Data Engineer, BI-аналитик, специалист ИБ | Сократить время подготовки отчётов |
| Год 2, 1-2 квартал | Масштабирование | Подключить ИИ-исследования, фарма-партнёров и медоборудование как новые источники событий | Data Product Owner, Data Engineer | Быстрее запускать новые направления |
| Год 2, 3-4 квартал | Перенос отчётов | Перенести основные отчёты со старого DWH на новые витрины | BI-аналитик, Data Engineer | Уменьшить зависимость от старого DWH |
| Год 3, 1-2 квартал | Снижение роли старых систем | Оставить старый DWH и Camel только для редких сценариев и чтения архивных данных | Архитектор, Data Engineer | Снизить стоимость сопровождения |
| Год 3, 3-4 квартал | Поддержка доменов | Ввести регулярную проверку качества данных, стоимости платформы и технического радара | Data Product Owner, BI-аналитик, архитектор | Поддерживать качество и управляемость платформы |

## Контрольные результаты

| Результат | Когда считается выполненным |
| --- | --- |
| Домены выделены | У каждого домена есть владелец данных |
| Пилот Data Mesh завершён | Пациентский и финансовый домены публикуют события и наборы данных |
| Self-service BI запущен | Бизнес-пользователь строит отчёты через портал |
| Новые источники подключены | ИИ, фарма-партнёры и медоборудование передают события |
| Старые системы разгружены | Основные отчёты больше не зависят от старого DWH |

## Краткий вывод

Data Mesh нужно внедрять постепенно: сначала пилот на двух основных доменах, затем подключение новых направлений, после этого перенос отчётов и снижение зависимости от старого DWH и Camel.
