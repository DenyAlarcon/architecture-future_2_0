# Расширенный технический радар

## Статусы

| Статус | Значение |
| --- | --- |
| Adopt | Использовать как стандарт для целевой архитектуры |
| Trial | Применить на пилоте и расширять после проверки |
| Assess | Изучить и проверить на небольшой задаче |
| Hold | Не использовать в новых решениях, постепенно выводить |

## Радар

| Направление | Технология или паттерн | Статус | Зачем нужен |
| --- | --- | --- | --- |
| Архитектурные паттерны | Data Mesh | Trial | Разделить ответственность за данные между доменами |
| Архитектурные паттерны | Событийная архитектура | Trial | Уйти от прямых связей через Camel и быстрее передавать изменения |
| Архитектурные паттерны | Self-service BI | Trial | Дать бизнесу возможность строить отчёты без постоянной помощи аналитиков |
| Архитектурные паттерны | Границы доменов | Adopt | Понятно разделить медицинский, финансовый и новые домены |
| Архитектурные паттерны | Централизованный DWH как единственный источник данных | Hold | Старый подход плохо масштабируется при росте доменов |
| Платформа данных | Data Lakehouse | Trial | Хранить исходные данные и аналитические таблицы в одной платформе |
| Платформа данных | Объектное хранилище | Adopt | Дешёвое и масштабируемое хранение данных |
| Платформа данных | Таблицы Data Lakehouse | Trial | Хранить подготовленные аналитические данные |
| Платформа данных | Каталог данных | Trial | Показывать владельцев, описание и качество наборов данных |
| Платформа данных | SQL Server 2008 DWH | Hold | Оставить только на время миграции |
| Интеграции | Платформа событий | Trial | Передавать доменные события между системами |
| Интеграции | Проверка схем событий | Assess | Проверять формат событий перед публикацией |
| Интеграции | Загрузка изменений из старых систем | Trial | Переносить изменения из старого DWH во время миграции |
| Интеграции | Apache Camel для новых интеграций | Hold | Не расширять старую шину новыми сценариями |
| Безопасность и эксплуатация | Управление доступом | Adopt | Управлять доступом по ролям и доменам |
| Безопасность и эксплуатация | Аудит доступа к данным | Adopt | Фиксировать обращения к чувствительным данным |
| Безопасность и эксплуатация | Мониторинг событий и отчётов | Adopt | Видеть задержки, ошибки и проблемы с отчётами |
| Инструменты разработки | Terraform | Adopt | Управлять инфраструктурой как кодом |
| Инструменты разработки | Проверка Terraform в CI/CD | Adopt | Проверять изменения инфраструктуры до применения |
| Инструменты разработки | Автоматические проверки качества данных | Assess | Проверять полноту, свежесть и схемы наборов данных |

## Краткий вывод

В ближайшие три года стоит развивать Data Mesh, событийную архитектуру, Data Lakehouse, каталог данных и self-service BI. Старый DWH и Apache Camel нужно оставить только как временные источники на время миграции.
